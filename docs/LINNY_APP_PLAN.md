# 리니 휠체어 덮개: 휴대폰 화면(웹앱) 개발 계획서 v1

작성 2026-11-17 · 28조(B-3.G28) · 코드로 처음부터 새로 만들기 위한 계획서.
코딩 도구(Claude Code 등)에 이 파일을 통째로 주고 "이 계획서대로 M1부터 만들어 줘"라고 하면 된다.

## 1. 무엇을 만드나

서울상상나라 2층 "뿜뿜! 펀 에너지" 전시를 휠체어 아이가 함께 즐기게 하는 프로토타입의 **휴대폰 쪽 프로그램**.

- 휠체어(프로토타입은 학교 의자)에 리니 모양 덮개를 씌우고, 무릎 위 받침판에 안드로이드 휴대폰을 가로로 고정한다.
- 전시물 옆 표지의 RFID 카드에 리니 코를 대면, 휴대폰에 그 전시의 **미션**이 뜬다.
- 아이가 휠체어로 미션 동작을 하면 진행도가 차고, 끝나면 **에너지 1개**가 만들어진다.
- 전시 3곳에서 3개를 모으면 배터리가 가득 차고, 똥버스 정류장 카드에 대면 에너지가 **전달**된다.

| 전시(카드) | 미션 동작 | 동작 이름 | 화면 |
|---|---|---|---|
| 발로 콩콩 물이 퐁퐁 | 앞뒤로 왔다 갔다 | `pump` | 물이 차오르고 싹이 자람 |
| 신나는 댄스마루 | 좌우로 살랑살랑 | `dance` | 전구가 하나씩 켜짐 |
| 울끈불끈 아지트(임시, 현장 확인 필요) | 제자리에서 빙글 | `spin` | 발전기 바늘이 올라감 |
| 달려라 똥버스 정류장 | 3개를 모은 뒤 카드 대기 | (없음) | 버스 출발 |

에너지가 아닌 것도 구분한다: `move`(그냥 이동), `still`(정지).

## 2. 정해진 것(바꾸지 말 것)

- **형태:** 웹앱. 정적 파일만(HTML, CSS, JS). 서버 없음. GitHub Pages(https)에 올린다.
- **대상:** 안드로이드 크롬, 가로 화면(약 844 × 390 기준, 다른 크기에서도 깨지지 않게 vw/vh 사용).
- **센서:** 휴대폰 내장 IMU를 `devicemotion` 이벤트로 읽는다. https 필수. iOS는 `DeviceMotionEvent.requestPermission()`.
- **보드 연결:** Web Bluetooth로 HM-10 계열 BLE 모듈(서비스 `0xFFE0`, 특성 `0xFFE1`)에 연결. 아이폰은 미지원이라 안드로이드만 대상.
- **라즈베리파이는 쓰지 않는다.** 판단은 전부 휴대폰에서 한다.
- **빌드 도구 없이** 시작한다(프레임워크, 번들러 없음). 파일을 그대로 올리면 동작해야 한다.
- **아이용 화면은 글자를 최소로**, 그림과 숫자를 크게. 필요 없는 화면 요소는 감점 사유다.
- **색:** 초록 `#5AB953`, 짙은 초록 `#0F4A34`, 노랑 `#FFD84A`, 바탕 `#F3FBF1`.
- 리니·워니 캐릭터 그림은 넣지 않는다(공식 파일을 받기 전까지 자리만 비움).

## 4. 놀이 규칙(상태 기계)

상태: `home` → `mission(pump|dance|spin)` → `done` → `home` … → `full` → `sending` → `home`

- `home`에서 전시 카드 접촉: 아직 안 끝낸 전시면 그 미션 시작. 이미 끝낸 전시면 "이미 모았어!" 안내만.
- `mission` 중: **그 미션의 동작으로 판단된 경우에만** 진행도 +20(5번이면 완료). 다른 동작, 이동, 정지는 무시.
- `mission` 중 다른 전시 카드 접촉: 지금 미션을 멈추고(진행도는 0으로) 새 미션 시작.
- `mission` 중 정류장 카드 접촉: "아직 에너지가 모자라!" 안내.
- 진행도 100 → `done` 3초 → 완료 수가 3이면 `full`, 아니면 `home`.
- `full`에서 정류장 카드 접촉 → `sending` 10초 → 전부 0으로 되돌리고 `home`.
- 어느 상태든 90초 동안 아무 일도 없으면 전부 0으로 되돌리고 `home`.
- **카드가 안 읽힐 때 대비:** 홈의 전시 카드 그림을 2초 누르면 그 미션 시작, 가득 참의 배터리를 2초 누르면 전달. 왼쪽 위 구석 2초 → 준비 화면.
- 주소 끝 `?debug=1`이면 화면 아래에 시험 버튼(카드 4종, 동작 3종, 처음으로).

## 5. 동작 판단

1. `devicemotion`에서 `accelerationIncludingGravity`(x,y,z)와 `rotationRate`(beta=x, gamma=y, alpha=z, 도/초)를 받는다.
2. 타임스탬프로 **정확히 50Hz(20ms 간격)** 가 되게 선형 보간한다. 250ms 넘게 끊기면 버퍼를 비운다.
3. 중력 방향을 저역 필터(시정수 1초)로 추정해, 휴대폰이 기울어져 있어도 같은 뜻의 6채널로 바꾼다:
   `yaw`(수직축 회전), `tilt`(그 밖의 회전 크기), `hx`·`hy`(수평 가속도 두 방향), `v`(수직 가속도), `hmag`(수평 크기).
4. **2초 구간(100샘플)을 0.5초마다** 잘라, 채널마다 평균·표준편차·최소·최대·절댓값 평균·방향 바뀐 횟수 = 특징 36개.
5. 판단기 두 개를 **항상 같이** 돌린다.
   - 규칙(비ML 기준선): 고정 기준값으로 `spin / pump / dance / move / still`.
   - 모델: 학습한 랜덤 포레스트(`model.json`). 없으면 규칙만 쓴다.
6. 결정: 판단이 현재 미션 동작이고 확신 0.8 이상이 **2번 연속**이면 +20, 이후 1초는 쉰다.
7. **루프 기록:** 미션 중 판단 한 번마다 한 줄(시각, 상태, 미션, 모델 판단, 확신, 규칙 판단, 올렸는지, 진행도, 처리 시간)을 메모리에 쌓고 CSV로 내려받을 수 있게 한다. ACDT 제출 증거다.

학습은 컴퓨터에서 한다(파이썬, scikit-learn). 휴대폰은 녹화 CSV를 만들고 `model.json`을 불러와 쓰기만 한다. **휴대폰 쪽 특징 계산과 파이썬 쪽 특징 계산은 숫자가 똑같아야 한다.**

## 6. 보드와 주고받는 말(BLE, 9600bps, 한 줄 20글자 이내)

| 방향 | 형식 | 뜻 |
|---|---|---|
| 보드 → 휴대폰 | `T:<카드 번호 16진수>` 예 `T:04A1B2C3` | 카드가 닿았다 |
| 보드 → 휴대폰 | `H` | 1초마다. 살아 있음 |
| 휴대폰 → 보드 | `<모드>,<a>,<b>,<c>*<검사값>` 예 `1,60,0,1*2C` | 0.3초마다 계속 보냄 |

- 모드: 0 홈, 1 미션 중, 2 미션 완료, 3 가득 참, 4 전달.
- a: 미션 진행도 0~100. b: 미션 번호(0 pump, 1 dance, 2 spin). c: 완료한 전시 비트(1 pump, 2 dance, 4 spin).
- 검사값: `*` 앞 글자를 모두 XOR 한 두 자리 16진수.
- **카드 등록:** 준비 화면에서 "물 퐁퐁 등록"을 누르고 카드를 대면 그 번호를 그 전시로 저장한다(localStorage). 카드 4장 모두 등록.
- 연결이 끊겨도 화면 쪽 놀이는 계속되어야 한다. 끊기면 2초마다 다시 잇기를 시도한다.

보드(아두이노 우노) 코드는 이 계획서 범위 밖이지만, 위 형식에 맞춰 따로 고친다.

## 7. 파일 구조

```
index.html        화면 전부(준비, 녹화, 점검, 놀이)
style.css         모양
core.js           계산만: 50Hz 맞춤, 채널, 특징, 규칙, 모델 추론, 결정, 상태 기계, 검사값
app.js            화면, 센서 이벤트, 블루투스, 녹화, 저장
model.json        (선택) 학습한 모델
tests/core.test.js   node로 돌리는 core.js 시험
tools/train.py    녹화 CSV → model.json, 규칙과 모델 비교 보고서
```

`core.js`는 화면과 무관하게 node에서도 돌아가게 만든다(시험과 파이썬 검산을 위해).

## 8. 만드는 순서와 통과 기준

| 단계 | 만드는 것 | 통과 기준 |
|---|---|---|
| M1 | 화면 7개 + 상태 기계 + `?debug=1` 시험 버튼 | 버튼만으로 홈 → 미션 3개 → 가득 참 → 전달 → 홈이 돈다. `tests/core.test.js` 통과 |
| M2 | 센서 읽기 + 규칙 판단 + 점검 화면 | 실제 휴대폰에서 센서가 초당 50번 이상. 손에 들고 돌면 `spin`으로 나온다 |
| M3 | 녹화 화면 | 60초 녹화가 3,000줄 CSV로 내려받아진다. 파일 이름 `날짜_장소_사람_동작_방식_번호.csv` |
| M4 | 블루투스 연결 + 카드 등록 | 카드를 대면 해당 미션이 시작된다. 보드 전원을 뺐다 꽂으면 스스로 다시 이어진다 |
| M5 | `train.py` + 모델 불러오기 | 휴대폰 계산과 파이썬 계산의 특징값이 같다. 모델을 넣으면 "학습한 모델"로 표시된다 |
| M6 | 소리, 진동, 화면 꺼짐 방지, 전체 화면, 홈 화면에 추가 | 30분 켜 두어도 화면이 안 꺼진다 |

각 단계가 끝나면 GitHub Pages에 올려 **실제 휴대폰에서** 확인한다. 컴퓨터에서만 되는 것은 통과로 치지 않는다.

## 12. 개발 환경 만들기(GitHub와 폴더)

### 한 번만 설치
| 프로그램 | 쓰임 |
|---|---|
| 크롬 | 컴퓨터에서 화면 확인 |
| GitHub Desktop | 폴더를 GitHub에 올리고 내려받기(명령어 없이 버튼으로) |
| Claude Code(쓴다면) | 폴더 안에서 코드 작성 |
| 파이썬 3 | 컴퓨터에서 미리 보기(`python -m http.server`), 나중에 학습 |
| Node.js (선택) | `tests/core.test.js` 실행 |
| 아두이노 IDE | 보드 코드 올리기(M4부터) |

### 저장소와 폴더 만들기
1. github.com 로그인 → 오른쪽 위 **+** → **New repository** → 이름 `linny`, **Public**, "Add a README file" 체크 → Create.
2. GitHub Desktop 로그인 → **File → Clone repository** → `linny` 선택 → 저장 위치는 `문서/linny` → Clone. 이 폴더가 작업 폴더다.
3. 폴더 안에 `docs` 폴더를 만들고 이 계획서와 `linny_screens_reference.png`를 넣는다.
4. 조원을 함께 쓰게 하려면: 저장소 **Settings → Collaborators → Add people**.

### 주소 만들기(GitHub Pages)
저장소 **Settings → Pages** → Branch `main`, 폴더 `/(root)` → Save. 1~2분 뒤 `https://<아이디>.github.io/linny/` 가 생긴다. `index.html`이 폴더 맨 위에 있어야 한다.

### 매번 하는 일
1. 작업 폴더에서 코드를 고친다(Claude Code를 이 폴더에서 연다).
2. 컴퓨터에서 확인: 폴더에서 `python -m http.server 8000` → 크롬 `http://localhost:8000/?debug=1`.
3. GitHub Desktop에서 바뀐 파일 확인 → 아래 칸에 한 줄 설명 → **Commit to main** → **Push origin**.
4. 1~2분 뒤 휴대폰 크롬에서 주소를 새로 고쳐 확인한다. 예전 화면이 보이면 주소 끝에 `?v=2`처럼 숫자를 바꿔 붙인다.

### 올리면 안 되는 것
저장소가 Public이라 누구나 볼 수 있다. 녹화 CSV(`data/`)와 조원 이름·학번이 든 파일은 올리지 않는다. 폴더 맨 위에 `.gitignore` 파일을 만들고 `data/` 와 `out/` 을 적어 둔다.
